# Independent note storage (#9)

Implements the agreed [behavior](behavior.md)/[rich-note contract](data-model.md) in shared Room schema5. Engineer choices on 2026-10-12 use the owner's routine technical delegation. `notes` has id/title/body/plainText/createdAt/updatedAt, no task/list/subtask relationship or FK. IDs are cryptographically random UUID v4, collision-checked transactionally against all current entity tables; the other repositories now check notes too. `DatabaseProvider.getNoteRepository()` uses the existing shared database and worker-thread policy.

RichBodyCodec accepts exactly `tdmk.blocks`, numeric integer version1, ordered blocks (paragraph/heading/bullet), heading levels1–3 or explicit null for other kinds, ordered runs with text/bold. Every property is required, with no extras. Json syntax/tree parsing uses pinned kotlinx-serialization-json1.8.1 under the existing BOM; no compiler plugin/editor is needed. A private source scan rejects duplicate object keys including escaped equivalents, which a map/tree representation otherwise loses. Schema validation rejects unsupported formats/versions/kinds, wrong types/levels, invalid Unicode scalars and CR/LF inside runs. Empty blocks/runs and tabs remain valid. Encode validates typed construction too; canonical JSON may normalize incidental JSON spacing while preserving all block/run order, formatting and original text whitespace.

Plain text concatenates runs per block and joins blocks with exactly LF, without glyphs/heading prefixes/JSON properties. Example: heading `Trip`, bold bullet `Passport`, empty paragraph => `Trip\nPassport\n`. Saved body and derived plain text are written atomically with title/timestamps. Formatting-only edits count as changed saves even when plain text is identical. No folded-shadow/cache/query implementation is added; #26 owns full Unicode normalization/matching, while #24/#25 own cards/editor/autosave/navigation.

Create validates title/body first. Unicode White_Space edge trimming uses the common validator; a new blank title plus no non-whitespace visible body text returns null (discarded draft, no ID/timestamp/row). Empty heading/bullet/bold metadata alone is not meaningful. Meaningful body with blank title uses Untitled; nonblank title with an empty body is saved. Existing cleared notes retain ID/creation, become Untitled with the submitted valid empty body, and remain saved. Update returns the persisted Note; delete returns Unit. Unknown-ID read/update/delete raises NoSuchElementException and never recreates a deleted row.

Saved notes read updatedAt descending, createdAt descending, ID ascending. Successful changed title/body/format edits use max(previous update, injected millisecond clock), retaining ID/creation. Semantically unchanged content/title leaves the original row and timestamps untouched, even when JSON spacing differs; it therefore does not reorder notes. Dates/timestamps retain the common Instant/SQLite-millisecond contract. Source state and derived text stay coherent after failed SQL writes because each save is one transaction.

Every note read decodes/validates its stored rich body. Update validates the old stored body before accepting replacement content; unsupported/corrupt local bodies fail observably with IllegalArgumentException/serialization diagnostics, preserving the exact original body text and all other stored fields. No fallback, silent repair or empty/plain replacement is used; this stage also declines deletion when read validation fails. Diagnosis/recovery UX and backup-wide version rejection remain their own issues. A malformed record makes readAll fail rather than silently dropping the note from results.

Explicit 4-to-5 migration adds only the independent note table and retains existing list constraints. Schemas1–4 and full earlier chain remain, generated schema5 is tracked. Rich-body version1 is independent of Room schema5 and portable backup version1. Exported-schema4 device tests preserve Settings/list/task completion-pair/subtask check state through migration and later note writes/reopen. Actual independence tests delete tasks/populated lists without touching notes and delete notes without touching surviving domain records. No backup, alarms, editor, cards, search UI or optional formatting features are introduced. See [validation](task-9-validation.md) and [general migration/failure policy](storage-foundation.md).

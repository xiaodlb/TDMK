# Recurrence storage (#12)

Schema 6 stores templates, retained ordered revisions, ordered checklist prototypes and exclusions in normalized Room tables. Composite revision/prototype keys preserve their contract identity without new UUIDs or a JSON codec/dependency. Existing typed date/time converters and repository validation reject unknown frequencies, invalid dates, priorities, content, prototype order and reminder precision. Template IDs share the existing global UUID collision checks.

`RecurrenceRepository` exposes create/read/edit/enable/delete, exclusion reads and transactional `writeKnownBatch`. The latter commits caller-supplied valid due slots, fresh unchecked child IDs and the revision cursor together; it does not enumerate schedules. Daily/weekly/monthly nominal provenance includes original-day month-end clamps. Unique original slots, paired recurrence fields, immutable series/slot identity and disjoint live/excluded reservations are enforced in SQLite. Source revision references remain retained even after their effective cutoff changes.

Initial effectiveFrom is min(anchorDate, captured creation local day), with the anchor unchanged, following the [PM correction](https://github.com/xiaodlb/TDMK/issues/12#issuecomment-6133562484). Future-start content edits can append today's revision without early occurrences. Schedule edits require an anchor today or later. Later boundaries remain nondecreasing; equal-day revisions have empty intervals. Content edits replace only today's unfinished nonoverride occurrence and children. Schedule changes supersede unfinished nonoverride original slots from today without exclusions. History, past unfinished rows, overrides and exclusions remain retained.

Task content edits/reopening and every user child mutation mark recurring parents as overrides in the same transaction; generated children do not. Single deletion reserves the immutable original slot. Disabling retains everything. Series deletion removes all occurrences, including moved/history rows and children, then revisions/prototypes/exclusions. Custom-list deletion first removes owned series including moved occurrences, then reserves deleted occurrences from surviving external series; list removal/order compaction share that transaction. Unrelated notes/rows and the renamed default list remain protected.

Migration 5-to-6 copies every existing task and subtask field before replacing either table. Child foreign keys reference final `tasks`, since Android SQLite migration connections do not rewrite temporary foreign-key names on rename. Existing Settings/lists/notes are untouched, ordinary recurrence fields become null/false, and schemas 1–5 remain unchanged. No destructive fallback is added. See [validation](task-12-validation.md).

Automatic enumeration/catch-up is #13; UI and OS reminders/durable reminder cancellation are linked downstream scopes. Requested reminder configuration is persisted here. No new dependency, delivery service or schema beyond 6 is introduced.

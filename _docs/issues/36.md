## Goal

Verify real Room schema upgrades preserve data, or record the next-upgrade obligation when only one version exists.

## Acceptance criteria

- [ ] The repository exports and tracks the current Room schema; the validation record lists all actual schema versions and supported upgrade paths.
- [ ] For each real supported upgrade path, migration checks open a representative prior database and verify lists/tasks/subtasks/recurrence/history/notes/settings and their IDs survive according to #4.
- [ ] Formatted-note bodies, completion timestamps, and foreign-key/occurrence uniqueness rules remain valid after migration.
- [ ] An unsupported/incompatible upgrade cannot silently trigger destructive fallback or reset user data.
- [ ] If there is only one schema version, the record explicitly states that no upgrade path exists yet, verifies that schema export, and documents the required migration check for the next change instead of inventing a migration.
- [ ] The report lists executed commands and pass/fail results; required failures remain open rather than being marked checked.

## Out of scope

- Initial database setup is tracked in [#5](https://github.com/xiaodlb/TDMK/issues/5).
- Backup-based restore is tracked in [#33](https://github.com/xiaodlb/TDMK/issues/33).
- Server/schema synchronization is tracked in [#40](https://github.com/xiaodlb/TDMK/issues/40).

## Constraints

- Prerequisites: #5 and implemented schema from #6, #7, #8, #9, #12, and #15 where settings use Room; #4's preservation contract.
- Files/scope: Room migration checks, schemas and _docs/migration-validation.md; adjust an actual migration only to fix a demonstrated failure.
- Use Kotlin, Jetpack Compose, Material 3, and Room/SQLite as applicable. Version one works offline without accounts; optional sync planning remains [#40](https://github.com/xiaodlb/TDMK/issues/40). Do not add unrequested features.
- Follow [AGENTS.md](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/AGENTS.md), [scope](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/plan.md), and [process](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/process.md). Read _docs/behavior.md and _docs/data-model.md for agreed rules/contracts; required unresolved decisions block implementation. Read testing/design guides before relevant work when present and report missing guides.

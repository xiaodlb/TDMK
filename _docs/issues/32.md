## Goal

Export a consistent versioned offline backup to a user-selected document destination.

## Acceptance criteria

- [ ] Export produces a file with an explicit supported format version and the inclusion policy agreed in #3.
- [ ] A fixture with custom lists, tasks, subtasks, recurrence templates/occurrences, completed history, formatted notes, and agreed settings appears completely in the exported snapshot.
- [ ] All exported IDs/relationships and note formatting match #4's contract; no account credentials, SDK paths, or signing data are included.
- [ ] Android's document picker lets the user choose the destination; cancellation creates no misleading success result or local data mutation.
- [ ] Export is a consistent snapshot during concurrent edits, and a failed write reports an error instead of a successful/complete backup.
- [ ] A validation report demonstrates human-readable errors and documents the format/version for the restore issue.

## Out of scope

- Backup validation/restore transaction is tracked in [#33](https://github.com/xiaodlb/TDMK/issues/33).
- Settings controls is tracked in [#34](https://github.com/xiaodlb/TDMK/issues/34).
- Cloud sync contract is tracked in [#40](https://github.com/xiaodlb/TDMK/issues/40).

## Constraints

- Prerequisites: #3, #4, #5, #6, #7, #8, #9, and #12; settings data from #15.
- Files/scope: Backup serializer/snapshot and document-output boundary under app, backup-format documentation, and targeted export checks; no restore engine.
- Use Kotlin, Jetpack Compose, Material 3, and Room/SQLite as applicable. Version one works offline without accounts; optional sync planning remains [#40](https://github.com/xiaodlb/TDMK/issues/40). Do not add unrequested features.
- Follow [AGENTS.md](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/AGENTS.md), [scope](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/plan.md), and [process](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/process.md). Read _docs/behavior.md and _docs/data-model.md for agreed rules/contracts; required unresolved decisions block implementation. Read testing/design guides before relevant work when present and report missing guides.

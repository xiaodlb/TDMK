## Goal

Edit ordinary task fields in a bottom sheet over the current screen, using the selected saved task rather than creating another task. Deliver the real application details flow that later checklist, recurrence, and reminder controls can extend.

## Acceptance criteria

- [ ] Tapping the details area of an existing task row in the real app opens a Material 3 bottom sheet with that task's saved title, current list name/identity, optional date, High/Medium/Low priority, and optional plain short note. Completion remains a separate row action. Loading does not show another task's draft; load failure offers retry or dismiss without writing data.
- [ ] Save updates the selected task's title, existing list selection, optional date, priority, and short note; the sheet closes only after a successful write, the row and applicable current date/list view refresh without restart, and reopening plus offline application restart show the saved values. The task ID, createdAt, completion timestamp/day, subtasks, and recurrence slot identity remain intact; editing an occurrence affects only that occurrence under the existing override rule. Unchanged Save creates no duplicate and does not bump updatedAt.
- [ ] A whitespace-only title, invalid/out-of-range date, or invalid field/list combination cannot overwrite the saved task. Show an actionable field/error message and retain the draft for correction. A storage failure leaves the sheet and draft available for retry with the previous persisted task intact; repeated Save taps during a pending write cannot issue duplicate writes. A missing/deleted task or list is reported without silently creating a replacement or choosing a different list.
- [ ] The explicit-save policy below is documented and verified: Save alone commits; Cancel, Android Back when the keyboard is closed, outside tap, and swipe dismissal discard unsaved changes and return to the same underlying destination. Keyboard dismissal (including the first Back while the IME is open) hides only the keyboard and retains the draft/sheet; a subsequent Back discards it. Reopening loads saved values, no extra task is created, and pending writes cannot be dismissed or submitted twice.
- [ ] All fields and clearly labeled Save/Cancel remain reachable with a long multiline short note and keyboard open, in portrait/landscape and font scale 1.0/2.0. Light/dark rendering follows the shared theme and safe/IME insets without clipped or covered actions. Accessible labels, selected values, validation announcements, and focus allow editing and dismissing without relying solely on a swipe or icon; save/dismiss returns focus to the originating context (the row when still present).
- [ ] Changing a saved date retains any existing reminder time on the new date; removing the date clears it, and adding a date later does not restore it. Other edits preserve reminder metadata, checklist/completion state, and occurrence provenance. Verify dated-to-undated and undated-to-dated changes against applicable date/list filtering, and a seeded task with reminder metadata against the approved policy. Reminder pickers, alarm scheduling, permissions, and notification delivery remain in #28/#29.

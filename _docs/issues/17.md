## Goal

Edit ordinary task fields in a bottom sheet while keeping the current screen context.

## Acceptance criteria

- [ ] Tapping a task opens a bottom sheet with its saved title, list, date, priority, and optional short note.
- [ ] Saving valid edits updates the row and applicable date/list views immediately, preserves task identity, and survives application restart.
- [ ] Blank titles and invalid field combinations show actionable validation without silently losing the previous saved task.
- [ ] The agreed save/dismiss policy is documented and verified for Android Back, outside tap, swipe dismissal, and keyboard dismissal; no extra task is created.
- [ ] A long short-note field and large text remain reachable while the keyboard is open, with a clearly accessible save/dismiss path.
- [ ] Changing/removing a date preserves valid metadata or applies the approved reminder-date policy; alarm controls remain in #29.

## Out of scope

- Checklist UI is tracked in [#18](https://github.com/xiaodlb/TDMK/issues/18).
- Recurrence controls is tracked in [#19](https://github.com/xiaodlb/TDMK/issues/19).
- Reminder controls and rescheduling is tracked in [#29](https://github.com/xiaodlb/TDMK/issues/29).
- Individual deletion actions is tracked in [#27](https://github.com/xiaodlb/TDMK/issues/27).

## Constraints

- Prerequisites: #16 and #7; approved field/date rules from #2 and #4.
- Files/scope: Task details Compose sheet, its state/save integration, and focused interaction checks under app; no additional full-screen task editor.
- Use Kotlin, Jetpack Compose, Material 3, and Room/SQLite as applicable. Version one works offline without accounts; optional sync planning remains [#40](https://github.com/xiaodlb/TDMK/issues/40). Do not add unrequested features.
- Follow [AGENTS.md](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/AGENTS.md), [scope](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/plan.md), and [process](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/process.md). Read _docs/behavior.md and _docs/data-model.md for agreed rules/contracts; required unresolved decisions block implementation. Read testing/design guides before relevant work when present and report missing guides.

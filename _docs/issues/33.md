## Goal

Validate and transactionally restore supported backups without corrupting existing local data.

## Acceptance criteria

- [ ] A supported exported fixture restores its lists, tasks, subtasks, recurrence records, completion history, formatted notes, and agreed settings according to #3's replace/merge policy.
- [ ] Validation detects unsupported format versions, malformed fields, invalid IDs/relationships, duplicate occurrence identities, and unsupported note formats before applying writes.
- [ ] Rejected/canceled restores leave existing data intact and show a readable reason; interrupted/failed writes roll back the data transaction.
- [ ] Round-trip export/restore preserves stable IDs, relationships, completion timestamps, ordering, and formatting rather than duplicating records unexpectedly.
- [ ] After successful restore, recurrence and reminder reconciliation remove obsolete schedules and recreate only eligible alarms without duplicates.
- [ ] A targeted report includes successful round trip, each invalid-file case, and rollback; no partial restore is displayed as success.

## Out of scope

- Export engine is tracked in [#32](https://github.com/xiaodlb/TDMK/issues/32).
- Settings confirmation/progress UI is tracked in [#34](https://github.com/xiaodlb/TDMK/issues/34).
- Cloud/account recovery is tracked in [#40](https://github.com/xiaodlb/TDMK/issues/40).

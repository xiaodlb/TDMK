## Goal

Persist independent formatted notes and human-readable preview/search content.

## Acceptance criteria

- [ ] Create/read/update/delete preserve stable note ID, title, timestamps and formatted body after on-disk reopening, with IDs unique across implemented entities. Enforce #3/#4's new-entirely-blank discard, blank-title Untitled fallback, title-with-empty-body allowance and existing-cleared-note retention. Changed saves update timestamps by the contract; unchanged saves do not reorder notes, and saved reads use updatedAt descending/createdAt descending/ID ascending.
- [ ] The documented `tdmk.blocks` version-1 body round-trips paragraph/heading levels 1–3/bullet blocks, bold runs, Unicode and empty blocks without formatting/text loss. Preserve block/run order and body whitespace; formatting-only changes count as edits. No editor library, images, attachments or additional formatting features are introduced.
- [ ] Stored preview/search source is readable plain text, concatenating runs per block and joining blocks with LF exactly as #4 specifies, without heading/bullet glyphs or JSON attributes. Regenerate it atomically with each saved body; failures leave old title/body/plain text/timestamps coherent. Full Unicode folded-shadow caches/query matching remain #26, with no incorrect ASCII-only shadow placeholders here.
- [ ] Invalid/unsupported format identifiers/versions, malformed structure or invalid Unicode are rejected without partial writes. An incompatible/corrupt locally stored body produces an observable error, preserves original stored bytes and blocks rewriting rather than silently replacing it with empty/plain text; test rejected new content and failed attempts to overwrite a corrupt/unsupported existing record. Backup-wide rejection remains #32/#33.
- [ ] Notes have no task/list/subtask foreign keys or links. Tests delete ordinary tasks and populated custom lists and show note identity/formatting remain intact; deleting a note preserves unrelated task/list/subtask records. Unknown-ID operations have explicit checked outcomes without recreating deleted notes.
- [ ] Real Android API 36 persistence results cover rich round-trip, title/empty-content cases, changed/unchanged saves, atomic failure, deletion/independence and reopen. Add/register an explicit non-destructive Room 4-to-5 migration with generated schema 5 while retaining 1–4/full migration chain; exported schema-4 upgrade tests preserve Settings, lists, ordinary tasks/completion pairs and subtasks/check states, validate Room schema and verify further note writes/reopen. Existing persistence/local tests and debug build pass; record device/API/commands/results.

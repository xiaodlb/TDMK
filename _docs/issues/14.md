## Goal

Provide a minimal four-tab navigation shell with a Settings route from Home.

## Acceptance criteria

- [ ] A cold launch shows Home; the bottom navigation contains exactly Home, Tasks, Notes and Log in that order, with a visible selected state. Each tap shows its distinctly labeled placeholder and selecting one never displays another destination's content; Settings is not a fifth main tab.
- [ ] Home contains a visible, accessibly labeled Settings entry that opens the Settings placeholder. Android Back returns to Home in one step without exiting; repeated entry/back cycles do not accumulate Settings copies. The entry is not a misleading nonfunctional appearance control before #15.
- [ ] Selected tab and an open Settings route survive routine activity recreation/rotation through saved navigation state. Repeated taps on the selected tab do not stack duplicates; switching Home/Tasks/Notes/Log repeatedly and recreating still selects the expected destination, without persisting navigation as user settings or opening SQLite from Compose.
- [ ] Document the delegated Android Back rule for Home, Tasks, Notes, Log and Settings, including the root exit point and tab-switch history treatment, and verify every case on the live API 36 phone/emulator. Settings must return Home; main-tab behavior must be predictable and repeat taps must not add Back steps. Focused navigation tests plus actual launch/recreation/back evidence and relevant local tests/debug build are recorded; no feature-screen functionality is claimed.
- [ ] The minimal neutral Material 3 shell has readable labels, visible selection/focus and accessible click targets/semantics, with no duplicate icon/label announcements. Actual API 36 portrait/landscape checks at normal and enlarged 2.0 font scale show all four navigation labels and Settings access visible/operable, with content/navigation respecting status/navigation-bar insets; inspect screenshots as well as state assertions. Shared light/dark/manual appearance work remains #15.

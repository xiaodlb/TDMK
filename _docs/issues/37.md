## Goal

Review and fix concrete accessibility/usability defects in the implemented screens on the target Android phone.

## Acceptance criteria

- [ ] A review record names the phone/API, text-scale settings, TalkBack setup, and implemented screens tested.
- [ ] Navigation, task sheets/checklists, recurrence/reminder controls, note cards/editor, search, and backup/settings remain readable and operable with large text and the keyboard open.
- [ ] TalkBack exposes meaningful labels/states and a usable focus order for task completion, priorities, card selection, formatting, and destructive actions.
- [ ] Interactive controls have usable touch targets, light/dark content is readable, and priority/completion information is understandable without color alone.
- [ ] The record links concrete defects to their fixes or follow-up issues with reproduction details and evidence; required unfixed defects are not reported as passed.
- [ ] Changes retain the agreed minimal design and existing behavior, with relevant regression checks recorded.

## Out of scope

- Theme selection/persistence feature is tracked in [#15](https://github.com/xiaodlb/TDMK/issues/15).
- Full product acceptance walkthrough is tracked in [#38](https://github.com/xiaodlb/TDMK/issues/38).
- Editor functionality beyond accessibility defects is tracked in [#25](https://github.com/xiaodlb/TDMK/issues/25).

- Prerequisites: #14–#27, #29, and #34 as applicable to implemented screens; use existing design/testing guides if present.

Read _docs/behavior.md and _docs/data-model.md for agreed rules/contracts; required unresolved decisions block implementation. Read testing/design guides before relevant work when present and report missing guides.

## Goal

Persist custom task lists and their order, with exactly one stable default Inbox.

## Acceptance criteria

- [ ] Create, read, rename, reorder, and delete operations return persisted results matching the list contract in _docs/data-model.md.
- [ ] First initialization creates exactly one Inbox; repeated initialization and application reopening preserve its ID and never create another.
- [ ] Three custom lists retain their names and reordered positions after closing and reopening the database.
- [ ] Rename/delete attempts on Inbox follow the owner-approved protections from #2; invalid/blank names and duplicate-name behavior match the contract.
- [ ] Deleting a custom list applies the documented relationship/cascade policy atomically; failed writes leave the previous list/order intact.
- [ ] Targeted persistence results demonstrate these operations without requiring an account or network.

## Out of scope

- Task records and dependent task storage is tracked in [#7](https://github.com/xiaodlb/TDMK/issues/7).
- List-management UI and deletion confirmation is tracked in [#21](https://github.com/xiaodlb/TDMK/issues/21).
- Backup restore behavior is tracked in [#33](https://github.com/xiaodlb/TDMK/issues/33).

## Constraints

- Prerequisites: #5 and list identity/validation/deletion rules from #4 and #2.
- Files/scope: List entities/DAOs/repository/Inbox initialization and associated Room schema/checks under app; no screen implementation.
- Use Kotlin, Jetpack Compose, Material 3, and Room/SQLite as applicable. Version one works offline without accounts; optional sync planning remains [#40](https://github.com/xiaodlb/TDMK/issues/40). Do not add unrequested features.
- Follow [AGENTS.md](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/AGENTS.md), [scope](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/plan.md), and [process](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/process.md). Read _docs/behavior.md and _docs/data-model.md for agreed rules/contracts; required unresolved decisions block implementation. Read testing/design guides before relevant work when present and report missing guides.

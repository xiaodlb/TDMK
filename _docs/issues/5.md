## Goal

Provide a versioned Room database foundation that opens and reopens reliably without discarding local user data.

## Acceptance criteria

- [ ] Room and compatible code-generation tooling are configured with pinned versions and the app debug build succeeds.
- [ ] Database initialization and dependency wiring provide one shared database instance and do not open it directly from Compose screen code.
- [ ] An exported schema exists for the initial database version and is tracked; the documented migration policy forbids destructive fallback for user data.
- [ ] A phone/emulator persistence check or instrumentation report demonstrates opening, closing, and reopening the database without an error or unexpected reset.
- [ ] A failed/open-incompatible database condition is reported without silently deleting the file; the initialization policy is documented.

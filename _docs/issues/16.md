## Goal

Provide reusable task rows and title-first quick entry with correct list defaults.

## Acceptance criteria

- [ ] A reusable row shows title, completion control/state, readable High/Medium/Low cue and scheduled date when present; undated rows show no invented date/time. Document the chosen supporting metadata (for example current list or existing reminder/checklist summary), deriving it from real saved data without adding editor controls. Accessibility exposes task title/state/actions without duplicate decorative announcements.
- [ ] Completed-today rows remain visible with crossed-out titles in their applicable #10/#11 results; historically completed rows do not leak into active hosts. Priority is understandable beyond color, including dark mode. Existing completion-day/date/ordering rules remain authoritative rather than filtering all completed records out or inventing row-specific visibility.
- [ ] Title-only quick entry saves a validated nonblank title with Medium priority, undated/default optional metadata and a stable ordinary-task ID. The supplied custom-list context selects that list; date-view/Home contexts select the stable default list even after Inbox rename. No implicit Today date/reminder or new recurrence/checklist is added; optional field editing remains downstream.
- [ ] After one successful save, subscribed matching results show exactly one new persisted row without restart and clear/reset the input for another entry; repeated submit while saving does not duplicate records. Use existing repository/domain results: a title-only undated task appears in its list/Anytime, not forcibly in Today/Home's dated task sections. Verify custom-list and default-list contexts with actual persistence rather than only mocked callback counts.
- [ ] Blank/Unicode-whitespace-only or invalid-Unicode titles create no record; long titles remain readable/reachable. Cancellation creates nothing, failed save retains the editable draft with a clear error/retry outcome and does not claim success. Actual API 36 light/dark normal/enlarged 2.0-font portrait/landscape checks with the keyboard open show entry/save/cancel/error and completion/details targets reachable within safe insets; inspect rendered screenshots and record focused interaction/persistence evidence plus relevant existing tests/build.
- [ ] Completion and row-details request have separate accessible actions: each tap invokes exactly its intended operation once with the correct task ID. Existing complete/reopen behavior persists/updates the row and retains subtasks/date; an unchecked-child completion failure leaves parent/children/checkbox state unchanged with a clear outcome. Details taps only request the #17 integration and never complete/reopen; completion taps never request details.

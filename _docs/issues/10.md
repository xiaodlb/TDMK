## Goal

Produce deterministic task results for Today, Upcoming, Anytime, overdue, and custom lists with priority ordering.

## Acceptance criteria

- [ ] With a fixed local date, Today includes tasks scheduled that day; overdue includes unfinished tasks with earlier dates; Anytime includes undated tasks; list views include the correct membership.
- [ ] Upcoming uses the dedicated range approved in #2; Home's separate upcoming range ends on Sunday, with Monday treated as the first day of a week.
- [ ] Every task result uses High, Medium, Low ordering and the agreed equal-priority tie-breaker.
- [ ] A boundary-case result table/report covers dates just before/after midnight, Sunday/Monday, month/year boundaries, and undated tasks without treating dates as time slots.
- [ ] A controllable clock/date source makes the same dataset produce repeatable results; completed-task filtering integrates with #11 rather than inventing a conflicting rule.

## Out of scope

- Completion/reopening behavior is tracked in [#11](https://github.com/xiaodlb/TDMK/issues/11).
- Tasks UI is tracked in [#20](https://github.com/xiaodlb/TDMK/issues/20).
- Home UI is tracked in [#22](https://github.com/xiaodlb/TDMK/issues/22).
- Foreground date-change refresh is tracked in [#35](https://github.com/xiaodlb/TDMK/issues/35).

## Constraints

- Prerequisites: #7, and date/tie-breaker rules from #2 and #4.
- Files/scope: Task queries/domain date-filter and ordering logic under app plus focused deterministic checks; no screen layout.
- Use Kotlin, Jetpack Compose, Material 3, and Room/SQLite as applicable. Version one works offline without accounts; optional sync planning remains [#40](https://github.com/xiaodlb/TDMK/issues/40). Do not add unrequested features.
- Follow [AGENTS.md](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/AGENTS.md), [scope](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/plan.md), and [process](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/process.md). Read _docs/behavior.md and _docs/data-model.md for agreed rules/contracts; required unresolved decisions block implementation. Read testing/design guides before relevant work when present and report missing guides.

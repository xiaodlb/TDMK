## Goal

Perform and record the first-version offline acceptance walkthrough, creating small linked issues for discovered failures.

## Acceptance criteria

- [ ] A walkthrough document lists the build/commit, Android device/API, dataset, steps, expected result, actual result, and pass/fail for each scenario.
- [ ] The checklist covers task entry/editing, list management, subtasks, priorities, all date views, overdue retention, recurrence, reminders, separate formatting notes, per-tab search, Log, and backup/restore.
- [ ] Airplane mode, application restart, local-day/week transition, permission denial, and restore cancellation/invalid input each have an observed result.
- [ ] Completed-today/historical visibility, schedule-based recurrence with older overdue occurrences, independent notes, and High-to-Low ordering match _docs/plan.md and approved behavior.
- [ ] Every failure or unperformed required check is listed explicitly; each discovered defect has a linked, session-sized GitHub issue with reproduction steps instead of being silently omitted.
- [ ] The readiness statement distinguishes passed, failed, and unverified scenarios and does not declare the version ready while required failures remain.

## Out of scope

- Accessibility-specific fixes is tracked in [#37](https://github.com/xiaodlb/TDMK/issues/37).
- Packaging/signing documentation is tracked in [#39](https://github.com/xiaodlb/TDMK/issues/39).
- Post-v1 sync evaluation is tracked in [#40](https://github.com/xiaodlb/TDMK/issues/40).

## Constraints

- Prerequisites: The first-version features in #5–#35 and applicable checks in #36–#37; approved _docs/behavior.md and scope.
- Files/scope: _docs/acceptance-walkthrough.md and linked defect issues only; do not implement discovered fixes inside this validation task.
- Use Kotlin, Jetpack Compose, Material 3, and Room/SQLite as applicable. Version one works offline without accounts; optional sync planning remains [#40](https://github.com/xiaodlb/TDMK/issues/40). Do not add unrequested features.
- Follow [AGENTS.md](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/AGENTS.md), [scope](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/plan.md), and [process](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/process.md). Read _docs/behavior.md and _docs/data-model.md for agreed rules/contracts; required unresolved decisions block implementation. Read testing/design guides before relevant work when present and report missing guides.
- Do not close required defect issues as part of grooming. File actual failure follow-ups only when the walkthrough observes a failure.

## Goal

Refresh date-sensitive task views and completion history on resume and while the app remains open across local-day changes.

## Acceptance criteria

- [ ] With the app open across midnight, Today/overdue results advance and previously completed-today tasks leave active views for their proper Log group.
- [ ] On Sunday-to-Monday transition, Home's upcoming week boundary changes correctly without an application restart.
- [ ] Resuming after multiple days refreshes dates and invokes existing recurrence catch-up without duplicate occurrences.
- [ ] A manual date/timezone change uses #4's date interpretation and recomputes visible results while leaving date-only scheduled dates intact.
- [ ] A controllable-clock report or recorded device run demonstrates midnight, Sunday/Monday, a month/year boundary, and resume from background.
- [ ] Refresh registration does not multiply during navigation/recreation, and no exact midnight database move or new alarm engine is introduced.

## Out of scope

- Filter algorithms is tracked in [#10](https://github.com/xiaodlb/TDMK/issues/10).
- Completion domain rules is tracked in [#11](https://github.com/xiaodlb/TDMK/issues/11).
- Recurrence generator is tracked in [#13](https://github.com/xiaodlb/TDMK/issues/13).
- OS alarm clock/timezone reconciliation is tracked in [#30](https://github.com/xiaodlb/TDMK/issues/30).

## Constraints

- Prerequisites: #10, #11, #13, #20, #22, and #23.
- Files/scope: Application lifecycle/date-change observation and screen state refresh integration under app plus focused clock checks.

Read _docs/behavior.md and _docs/data-model.md for agreed rules/contracts; required unresolved decisions block implementation. Read testing/design guides before relevant work when present and report missing guides.

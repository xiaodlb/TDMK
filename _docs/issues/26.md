## Goal

Add search fields scoped to Home, Tasks, Notes, and Log while preserving each view's grouping and ordering.

## Acceptance criteria

- [ ] Each main tab exposes a search field that filters only the content defined for that tab in #3; Tasks preserves the selected date/list scope.
- [ ] A known fixture demonstrates title/body/short-note matching according to the approved fields and case/Unicode policy.
- [ ] Notes search matches human-readable text rather than formatting serialization, and Log searches completed history.
- [ ] Blank queries restore the complete scoped results; no matches show a clear state, and clear-search restores results immediately.
- [ ] Priority ordering, completion-day grouping, and note ordering remain correct while results are filtered.
- [ ] Edits/completion/deletion update visible search results without a restart; keyboard and large text keep field/clear controls accessible.

## Out of scope

- Search policy decisions is tracked in [#3](https://github.com/xiaodlb/TDMK/issues/3).
- Task filtering/ordering engine is tracked in [#10](https://github.com/xiaodlb/TDMK/issues/10).
- Note formatting editor is tracked in [#25](https://github.com/xiaodlb/TDMK/issues/25).

- Prerequisites: #20, #22, #23, and #24; matching and Home coverage from #3.
- Files/scope: Per-tab search UI/state and repository/query integration under app, with focused matching and view checks; no global search screen.
- Use Kotlin, Jetpack Compose, Material 3, and Room/SQLite as applicable. Version one works offline without accounts; optional sync planning remains [#40](https://github.com/xiaodlb/TDMK/issues/40). Do not add unrequested features.

Read _docs/behavior.md and _docs/data-model.md for agreed rules/contracts; required unresolved decisions block implementation.

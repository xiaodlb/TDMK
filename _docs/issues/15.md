## Goal

Provide a minimal light/dark theme with persisted System, Light, and Dark choices.

## Acceptance criteria

- [ ] Settings exposes accessibly labeled System, Light and Dark controls with exactly one visibly/semantically selected choice. Fresh-install default is System; opening Settings/recreating the activity never resets an already stored choice. Keep the shell's route/Back behavior intact.
- [ ] Selecting Light or Dark updates the shared theme for Home/Tasks/Notes/Log/Settings without restart and persists the selected manual override through activity recreation and an actual app process restart. A subsequent device appearance change does not override the manual selection; status/navigation-bar surfaces and icon contrast follow the resolved appearance rather than remaining hard-coded to #14's light shell.
- [ ] Selecting System immediately uses current phone appearance and responds to system light/dark changes while the app is running and after restart, without reinstall. Persist the choice system, not its temporary resolved light/dark value; tests switch from manual override back to System and show both device appearances correctly.
- [ ] One shared neutral Material 3 color/typography/spacing foundation keeps every current destination consistent, with readable text/system-bar contrast, visible focus/selection and usable appearance controls. Inspect actual light/dark Settings and navigation screenshots at normal and enlarged 2.0 font scale in portrait/landscape; no labels/controls are clipped or unreachable and #14 insets remain safe. A compact _docs/design-system.md records only the implemented roles/tokens and shell/control rules, linked from AGENTS.md, for later UI work; no full component library or screen redesign.
- [ ] Use the existing Room Settings singleton/Appearance encoding through safe shared background storage access; the feature works offline with no account/network or schema change. Persistence failure is observable and does not claim a successfully saved choice or overwrite other data; document/check the selected error outcome. Focused real API 36 mode-switch/recreation/process-restart/system-change tests and rendered inspection plus relevant existing navigation/local tests/debug build are recorded with commands/device/results.

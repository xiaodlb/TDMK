## Goal

Add checklist entry, editing, deletion, and independent completion within task details.

## Acceptance criteria

- [ ] The task sheet shows the parent's saved checklist in stored order and lets the user add a valid subtask.
- [ ] Editing or deleting one checklist item affects only that item; blank input is handled according to the model and failure leaves the prior state intact.
- [ ] Each checkbox changes that subtask independently, and the parent-completion/reopening result matches #2's policy.
- [ ] Closing/reopening the sheet and restarting the application retain item text, order, and checked states.
- [ ] With a long checklist, keyboard, and larger text, the active input and completion/delete controls remain accessible without covering the sheet actions.

## Out of scope

- Checklist storage contract/operations is tracked in [#8](https://github.com/xiaodlb/TDMK/issues/8).
- Recurring-task controls is tracked in [#19](https://github.com/xiaodlb/TDMK/issues/19).
- Whole-app accessibility review is tracked in [#37](https://github.com/xiaodlb/TDMK/issues/37).

## Constraints

- Prerequisites: #8 and #17; parent/subtask rules from #2.
- Files/scope: Checklist components inside task details, state/repository integration, and targeted checks under app.
- Use Kotlin, Jetpack Compose, Material 3, and Room/SQLite as applicable. Version one works offline without accounts; optional sync planning remains [#40](https://github.com/xiaodlb/TDMK/issues/40). Do not add unrequested features.
- Follow [AGENTS.md](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/AGENTS.md), [scope](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/plan.md), and [process](https://github.com/xiaodlb/TDMK/blob/codex/task-1-android-setup/_docs/process.md). Read _docs/behavior.md and _docs/data-model.md for agreed rules/contracts; required unresolved decisions block implementation. Read testing/design guides before relevant work when present and report missing guides.

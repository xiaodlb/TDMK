## Goal

Add checklist entry, editing, deletion, and independent completion within the real task-details bottom sheet, retaining the selected parent and its saved data.

## Acceptance criteria

- [ ] The task sheet shows the parent's saved checklist in stored order and lets the user add a valid subtask. Open it from an existing row in the real app, including a parent with no children. New entries append unchecked; Unicode text and duplicate item text are supported with distinct stable identities. Loading/retrying or switching parents never displays another parent's checklist or writes data.
- [ ] Editing or deleting one checklist item affects only that item; blank input is handled according to the model and failure leaves the prior state intact. Reject blank/Unicode-whitespace-only or invalid Unicode labels with an actionable error and keep the draft for correction; trim valid label edges without changing internal spaces. Edit preserves the child's ID, order and checked state. Delete names the item and requires permanent-deletion confirmation; cancel leaves it intact. Saving confirmed deletion removes only that child and compacts remaining order, including deleting the last child. Invalid input/storage failure leaves all previously persisted parent/child data intact; keep the open draft for retry, and prevent duplicate submissions/dismissal during a write. Missing/deleted parent or child is reported without recreating it or targeting an item with the same text.
- [ ] Each checkbox changes that subtask independently, and the parent-completion/reopening result matches #2's policy. Checking the final unchecked child does not automatically complete its parent; explicit parent completion succeeds only when every saved child is checked (also for zero children). A blocked attempt leaves the parent and child states unchanged and reports the reason. Saving an unchecked added child or unchecking an existing child of a completed parent atomically reopens that parent, retaining date/absence of date and other child states. Text edits/deletion alone preserve completion timestamp/day. Rechecking after reopening requires a separate parent-completion action. Verify the row/current view refresh after successful Save and the existing row completion action uses the saved checklist gate.
- [ ] Closing/reopening the sheet and restarting the application retain item text, order, and checked states. Checklist changes follow the explicit Save policy below: successful Save persists the entire task/checklist draft together; Cancel, outside tap, swipe and Back with keyboard closed discard it. First Back with keyboard open hides only the keyboard and retains draft/sheet. Configuration recreation retains the draft; process restart may discard an unsaved draft. Verify committed add/edit/check/delete across offline application restart and preserve parent ID/createdAt, unrelated task fields, other parents/children, and occurrence provenance. Editing an occurrence's checklist marks only that occurrence's override; other occurrences/template prototypes remain unchanged. Parent/list cascade deletion during editing cannot resurrect deleted records on Save.
- [ ] With a long checklist, keyboard, and larger text, the active input and completion/delete controls remain accessible without covering the sheet actions. Inspect real device/emulator rendering in light/dark, portrait/landscape, font scale 1.0/2.0, including duplicate/long labels and long short note. Inputs, each item's check/edit/delete actions, confirmation and Save/Cancel remain reachable by scrolling/focus with safe/IME insets; controls have understandable accessible labels, checkbox role/checked state, adequate touch targets and polite validation announcements. Do not rely only on swipes or unlabeled icons. Preserve #17 keyboard/dismissal behavior and focus return to the originating context, including after parent reopening changes the visible view.

## Goal

Persist ordered subtasks and independent check states for a parent task.

## Acceptance criteria

- [ ] Create, edit, reorder, check/uncheck, and delete operations affect only the intended parent checklist/subtask; stable subtask IDs are preserved on edits/reorder/check changes and are unique across implemented lists/tasks/subtasks. Stored fields match #4 (ID, parent FK, Unicode-trimmed nonblank text, contiguous zero-based order, false-default independent checked state); new items append and deleting compacts order.
- [ ] Real Android API 36 on-disk checks demonstrate a multi-item checklist retaining every ID/text/order/checked state through close/reopen and further writes. Add/register explicit non-destructive Room 3-to-4 migration, track schema 4 without modifying schemas 1–3, and validate migration from exported schema 3 with existing Settings/lists/dated, undated and completed tasks preserved; retain the full earlier migration chain. Existing persistence/local checks and debug build pass, with device/API/commands/results recorded.
- [ ] All parent-completion write paths, including existing TaskRepository.complete/setCompletion, enforce #2's gate in the same transaction: mixed checklist blocks parent completion without auto-checking children; all checked or no children permits explicit completion, while checking the final child never auto-completes. Reopen clears both completion fields and retains date/check states. Unchecking or adding an unchecked child under a completed parent atomically reopens it, retaining other states/date/reminder configuration, and existing active/completed observers receive the change. Deleting a child preserves parent completion state and never auto-completes; examples cover mixed/fully checked/no-child cases and captured completion day preservation.
- [ ] Deleting a parent cascades to its subtasks atomically using #4's task FK CASCADE, including parents removed by the current custom-list deletion transaction; unrelated parents/children survive. Adding under a nonexistent parent is rejected without an orphan. A targeted injected failure in multi-record mutation verifies children/parent completion/list state all roll back rather than exposing partial deletion or reopening.
- [ ] Blank/Unicode-whitespace-only or invalid-Unicode text, duplicate/missing/unknown IDs in a checklist reorder, and unknown subtask/parent IDs are rejected with explicit checked outcomes and no partial write. Enforce unique (parent, order); each parent's reorder is a complete permutation of its own children and cannot move another parent's child. Write failures preserve prior text/order/check/completion state, demonstrated by targeted persistence checks.

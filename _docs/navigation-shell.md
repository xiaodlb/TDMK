# Navigation shell (#14)

The four main tabs are Home, Tasks, Notes and Log in that order. A cold launch starts Home. Home's labeled Settings button opens a distinct Settings placeholder; it exposes no appearance controls before #15. Main destinations remain placeholders for their linked feature issues.

Back choice under the owner's 2026-10-12 delegation: Settings→Home; Tasks/Notes/Log→Home; Home is the root exit point handled by Android. Switching tabs replaces the selected main destination, without retaining tab history. Repeated taps never add a Back step. Example: Home→Tasks→Notes→Log→Log, Back→Home, Back→Android launcher/background. Repeated Settings entry/Back always returns Home once. The visible Settings back button has the same behavior as Android Back.

One `rememberSaveable` route preserves selected tab or Settings across recreation/rotation. Navigation is transient, never written as appearance/user settings; Compose opens no SQLite/provider/domain data. No navigation framework/dependency is needed for these five routes. Material3 Scaffold/top app bar/navigation bar own their system insets, with safeDrawing/consumed content padding and scrollable placeholder content at large font sizes. Main icons are decorative (null descriptions); each navigation item's visible text supplies its single accessible label and selected semantics. Built-in Material3 target sizes, focus/selection and typography are retained. Shared appearance remains #15.

Necessary test-only Compose `ui-test-junit4` uses the app's existing BOM2025.08.00, with no application dependency upgrade. [Official test setup](https://developer.android.com/develop/ui/compose/testing) and [Material3 inset guidance](https://developer.android.com/develop/ui/compose/system/material-insets) support the setup. Actual Activity tests need no empty test-activity manifest. Design/testing guides are absent; existing minimal neutral Material3 scope applies. Device/rendering evidence is recorded in [validation](task-14-validation.md).
